## Remaining external dependencies and constraints

- Real accounts, email verification, owner isolation and cloud persistence require a Supabase project URL and **publishable/anon** key, database migrations/RLS and a configured email/redirect policy. A service-role key must never enter the frontend or this repository. The connected flow cannot be verified against a real provider until that configuration exists.
- Agronomist validation, location-specific citations, real phone testing, production backup/monitoring, legally reviewed privacy/terms and public deployment cannot be honestly completed by writing client code alone. Public deployment remains subject to the user's existing instruction to ask first.
- The reference screenshots contain estimated yields and revenues and imply OCR from uploads. The PDF requires supporting data, explicitly disallows unsupported numeric forecasts and says upload alone does not analyze soil. Those items will not be presented as real capabilities without evidence.
